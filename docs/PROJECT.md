# Project

## Name

**Aevum**

Aevum supersedes the former working name **LifeOS**. New repository documentation and implementation should use **Aevum** terminology.

## Vision

Aevum is intended to become a durable personal organizational intelligence system: a place where meaningful life context can be captured, structured, revisited, and eventually understood with AI assistance.

The long-term objective is not merely to store information. Aevum should help make accumulated personal context more useful for reflection, decision-making, planning, continuity, and understanding over time.

## Intended users

Aevum is designed as a **general-purpose personal system**, not a developer-only productivity tool. Its concepts should remain understandable for people managing ordinary goals, decisions, activities, reflections, and life events.

## Product principles

1. **Life-first, not project-first.** The product should model a person's life rather than force all life activity into software-project structures.
2. **Context should compound in value.** Information captured today should remain useful later through organization, retrieval, relationships, and AI assistance.
3. **AI should be integrated deliberately.** AI is a foundational capability, but deterministic application behavior should not be replaced by unnecessary model calls.
4. **Privacy is architectural.** Personal information, model context, retention, external processing, and security boundaries must be considered explicitly.
5. **Repository truth over conversation history.** Approved decisions and specifications belong in version-controlled documentation.
6. **Small, reviewable implementation phases.** BUILD work should be scoped so that it can be implemented, tested, reviewed, and committed independently.

## Current project state

Aevum is currently in **Repository Baseline v1** initialization. Historical planning is frozen through **Phase 3B.8** while the project transitions to the PSB Workflow.

Application implementation has not started.
