# Architecture Decision Records

Use this directory for significant architectural decisions that require more rationale than the summary maintained in `docs/DECISIONS.md`.

## When to create an ADR

Create an ADR when a decision:

- materially changes architecture or technology;
- has meaningful alternatives or tradeoffs;
- constrains multiple future phases;
- supersedes an earlier architectural choice;
- would otherwise be repeatedly reconsidered.

Do not create an ADR for every implementation detail.

## Suggested format

```markdown
# ADR-XXXX — Decision title

Status: PROPOSED | ACCEPTED | SUPERSEDED | REJECTED
Date: YYYY-MM-DD
Supersedes: optional ADR

## Context
## Decision
## Alternatives considered
## Consequences
## Follow-up
```

`docs/DECISIONS.md` remains the searchable decision register and should link to any ADR created here.
